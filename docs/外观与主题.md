# 外观与主题（浅色 / 深色 / 字号）

## 实现概览

- 入口在「我的 → 外观与显示」：外观三选一（跟随系统 / 深色 / 浅色）+ 全局文字大小滑杆（0.85–1.3）。
- 偏好只保存在当前浏览器 `localStorage`，不写入业务账号或服务端：
  - `zp_appearance_theme`：`system` | `dark` | `light`
  - `zp_appearance_font_scale`：0.85–1.3 的数字
- 实现在 `js/ui-unified.js` 顶部的 `initAppearancePreferences` IIFE，对外暴露：
  - `zpSetAppearanceTheme(theme)` / `zpGetAppearanceTheme()`
  - `zpSetFontScale(value)` / `zpGetFontScale()`
- 切换会派发 DOM 事件：`zp:appearancechange`、`zp:fontscalechange`（设置页监听它们刷新选中态）。

## 主题生效机制

- `applyTheme` 把解析结果写到 `<html data-zp-theme="light|dark">`，并同步 `meta[name=theme-color]`。
- CSS 侧约定（2026-10-23 基底反转后的现行口径，与本文档早期版本相反）：
  **浅色是 `:root` 基座**，定义在 `css/ui-base.css`；深色只在 `css/ui-theme.css` 的
  `:root[data-zp-theme="dark"]` 里覆盖同名令牌。历史「浅色补丁层」
  （`:root[data-zp-theme="light"] .xxx` 逐条覆盖）已于 2026-10-29 全部删除，
  组件里不再出现任何第二套主题规则。
- 令牌唯一真相源是上面两个文件，`css/home.bundle.css` 是其构建产物（`scripts/build-home-bundle.mjs`）。

### 列表容器 vs 内容卡（2026-11-04）

色值已经与 Uber App 截图逐像素一致（浅 `#FFFFFF`/`#F3F3F3`、深 `#161616`/`#292929`），
但观感仍不像，原因不在色值而在**色块面积**：Uber 截图里灰块只占 13%，账号页卡片铺了
52%——同一对比度下，点状分布显得「黑」，满铺显得「灰」。所以这轮不动色值，只把列表
容器的面积让出去。

- `--zp-card-list` = `--zp-bg`：容器与页面同色，分组退化为「小标题 + 行 + 行线」。
  目前用于 `.acct-card`（账号分组）、`.dispatch-action-card`（线路功能）、
  `.history-list`（历史月份分组）。
- `--zp-card` 不变：内容卡仍保留块色。**不要**把 `--zp-card` 直接指向 `--zp-bg`，
  否则任务卡、线路卡、派单卡一起拍平，整页失去层级。
- 行线因此成为分组内唯一的分隔手段，`--zp-line-inset` 需保证「看得见但不硬成框」：
  浅色对白底 1.23、深色对 `#161616` 为 1.28。深色取 `#323232` 会到 1.41，视觉上
  像表格框线，故压到 `#2B2B2B`。
- **分组之间用空白，不用更粗的线**。历史页原先靠「卡片边框 + 月份线 + 行线」三层叠加，
  卡片取消后两条线挤在一起，月份标题和日期行分不出主次；现改为相邻分组留 14px 空白、
  组内行保留细线——层次靠节奏，不靠线的深浅。新增多分组列表时沿用这一条。
- 新增列表页时：容器用 `--zp-card-list`，行分隔用 `--zp-line-inset`，末行
  `border-bottom:0`；不要在容器上再写 `box-shadow`（底色与页面同色后投影无附着点）。

## 输入框（2026-10-29 统一）

- 全站输入控件只有一套外观，由 `css/ui-base.css` 的「表单控件基座」供给：
  底 `--zp-input-bg`、边 `1px --zp-input-line`、圆角 `--zp-r-control`（12）、
  高 48（登录页 54 为历史豁免）、字号 15（登录/管理端弹窗 16）。
- 密码显隐包裹层 `.zp-password-control`、自定义下拉 `.zp-pk-trigger` 与原生
  `input/select/textarea` 共用同组令牌；`js/ui/zp-picker.js` 的 WebView inline 兜底
  （`triggerSurfaceStyle`）也输出这组令牌，不再按容器分叉。
- 禁用态不用整块 `opacity`（会把描边一起淡掉），改独立底色/描边/文字色；
  聚焦只改描边色 + 光晕，不加 `outline`（否则出现「黑环套蓝环」）。
- 新增输入类组件时**只写布局**（宽、高、间距），颜色一律取上述令牌；
  不要在页面 CSS 里再写 `background/border/color`。

## 按钮与刻度（基线 3.0）

- 字号 8 档、字重 4 档、行高 6 档、圆角 5 档、间距 6 档，全部走 `--zp-fs-*` /
  `--zp-fw-*` / `--zp-lh-*` / `--zp-r-*` / `--zp-sp-*`；守卫脚本
  `scripts/ui-token-guard.mjs` 禁止组件层写字面量（允许清单内除外）。
- 按钮唯一原语是 `.zp-btn`（`--primary/--secondary/--ghost/--danger/--mini/--icon/--block`），
  定义在 `css/ui-base.css` 末尾。

## 外壳 / 底栏 / 空态 / 弹层（2026-10-29 收编）

同一类"长得一样"的东西曾经各写一份，再靠 `!important` 与加载顺序拉齐。现在每类只有一个
来源，页面级文件只写布局：

| 组件 | 唯一来源 | 用法 | 不允许再做的事 |
|---|---|---|---|
| 页面外壳 | `main.zp-shell`（`css/ui-shell.css`） | 每页 `<main class="zp-shell 语义类">` | 页面容器类再写 width / max-width / min-height / margin / padding |
| 常驻底栏 | `.zp-nav`（`css/ui-base.css`） | `<nav class="zp-nav">` + `.zp-nav-item/-icon/-plus` | 页面前缀 + `!important` 重写底栏 |
| 空态 | `.zp-empty` / `.zp-empty--tight` | `<div class="zp-empty">暂无数据</div>` | 新起 `.xxx-empty` 类名 |
| 弹层 | `css/ui-overlay.css` 4.0 节 | `.order-dialog` / `.history-dialog` / `.data-import` / `.upload-overlay` | 组件再声明遮罩定位、面板宽度、圆角 |
| 顶栏 | `main > .topbar`（`css/ui-shell.css`） | `<header class="topbar">` 作 `<main>` 直接子元素 | 页面顶栏类再写安全区 / 底色 / 下间距 / `z-index` |
| 输入框包裹 | `.zp-password-control` / `.username-control`（`css/ui-base.css`） | 由 `js/ui/feedback.js` 自动生成，标记里不手写 | 上游「裸输入框」规则继续用后代选择器命中包裹内的 input |

- 外壳宽度读 `--zp-shell-max`（430），左右留白读 `--zp-gutter`（16，≤380 屏为 12）。
  改宽/改留白只改令牌，不碰页面。
- 底栏层级走 `--ui-z-nav`（40）；上传弹层打开时用 `calc(var(--ui-z-modal) + 1)` 递进，
  不再硬编码 1001。
- 顶栏层级走 `--ui-z-topbar`（10）。顶栏是文档流内的 flex 子项、不吸顶，层级只用于
  与底栏/悬浮件排同一次序；页面顶栏类只保留 `display` / 对齐等自身布局差异。
- 弹层面板统一 398 宽 / 18 圆角 / 12 遮罩内边距；上传面板是底部 sheet，单独 390 + 安全区。
- 隐私政策 / 服务条款（`pages/privacy.html`、`pages/terms.html`）按「沉浸阅读页」处理：
  只加载 `theme-sync.js`，不注入底栏，靠顶栏返回键回「我的」。这是分类，不是漏装 ——
  若要把它们并入常驻导航，正确做法是引入 `js/ui/core.js` + `js/ui/nav.js` 并给滚动区补
  底栏高度内边距，**不要在页面里手写一份导航**。
- 新增页面时挂 `zp-shell` 即可获得与全站一致的宽、居中、留白与滚动容器，
  **不要再自建 page 容器**。

### 裸控件规则必须收在直接子选择器

「字段里的裸输入框」与「被控件包裹的输入框」是两种东西。前者用 `.dialog .field>input`、
`.account-page .page2-label>input`（**直接子**）声明；后者由 `.zp-password-control` /
`.username-control` 自己负责，input 在里面要去框化（透明底、无边框、无内外边距）。

只要上游写后代选择器（`.dialog .field input`），包裹内的 input 就会被一起命中，
于是组件只能用 `!important` 反压 —— 这正是 2026-10-29 之前密码框 9 条强制声明的来源。
收紧为 `>` 之后组件回到普通级联，9 条全部删除，管理端密码框字号也随之与业务端统一为 15px、
文字左对齐（此前被裸字段规则的 `text-align:center` 拉成居中）。

### `!important` 配额（只减不增）

`tests/css-important-budget.test.mjs` 按文件固化当前 48 条基线，任何新增都会让
`npm run test:node` 变红。基线分两类：**机制必需**（层级令牌、`[hidden]` 对抗
`display:flex`、reduce-motion 总闸、隐藏原生 select）与**局部修饰**（单点颜色/过渡）。
需要新增时，先证明「普通级联 + 特异性」做不到，再改基线并写明理由。

## 字号缩放

- `applyScale` 把倍率写入 `<html style="--zp-font-scale">`，并对命中选择器的文本元素按「基准字号 × 倍率」写 inline `font-size !important`，范围钳制 0.85–1.3。
- 基准字号缓存在元素 `dataset.zpFontBase`，首次计算后复用；`MutationObserver` 对后续新增节点补应用。
- 已知边界：inline `!important` 会覆盖页面自身的动态字号调整；新增强字号语义的组件时需要评估。
