# 适配One · 运单处理新链路

## 正式链路

上传运单 → OCR识别 → 提取 → 匹配 → 去重 → 规划 → 待定/新增确认 → 保存 → 今日线路 → 历史 → 基准库学习

## 处理原则

- OCR只负责把图片变成原始文字，不直接决定门店身份。
- 提取负责从原始文字得到日期、车辆、门店及数量等结构化字段。
- 匹配负责把门店映射到线路基准库的storeId；优先身份ID，其次标准名/原始名/别名，最后才进行受控相似度匹配。
- 相似度匹配必须有明确阈值和置信差，无法确定进入待定，禁止强行归属。
- 去重以storeId为核心；待定门店也必须保留，不能因无法匹配而丢失。
- 规划使用基准库routeOrder；已匹配门店按线路顺序排列，待定/新增门店追加到末尾；无基准库时保持运单原始顺序。
- 格式变化（空格、换行、括号、常见标点、Ⅱ/II等）不计入“名称更正”。
- 整个识别到规划过程尽量在一次后端请求内完成，基准库只读取一次，减少前后端往返。
- 每个阶段记录耗时，便于真实回归时定位慢点，而不是笼统显示“匹配中”。

## 成熟产品借鉴后的边界

成熟配送系统通常把“订单处理/匹配”“路线规划”“实际调度”分层；规划完成后再进入路线计划和司机实际执行。适配One继续保持“绑定线路”和“当前调度线路”分离，不把司机绑定等同于当天调度。

## 当前版本状态

当前重建版已落地提取、匹配、去重、规划的后端核心骨架；图片OCR适配层仍作为独立下一阶段接入，避免把OCR失败与业务匹配/规划失败混在一起。
