# ADR 0005：品牌启动页固定深色，运行期外观可切换

- 状态：已采纳（2026-11-03，用户拍板）
- 影响面：Android 启动主题、Web 外观偏好、登录页品牌区、后续所有「启动闪变 / 状态栏颜色」类修复
- 相关：`docs/双项目优化规划-核查修正.md` §6.8、PR #193、`android/res/values{,-night}/colors.xml`、`js/ui/appearance.js`

## 背景

启动外观在过去一周被改了三轮，每一轮都能自证合理，但互相推翻：

| 时间 | 做法 | 出处 |
|---|---|---|
| 10-30（v1.0.21） | 启动色跟随系统：浅 `#F6F7F9` / 深 `#121826`，新增 `values-night` | 该版本启动优化 |
| 11-02 | 固定深色外观，统一品牌黑启动背景 | 提交 `ui: 固定深色外观并统一黑色启动背景 (#192)` |
| 11-02 稍后 | 恢复外观偏好（可切浅/深），仅启动页保留品牌黑 | `fix(theme): restore site appearance preferences` |
| 11-03 | PR #193 仍主张「固定深色主题」，与 main 冲突且无法直接合并 | PR #193 复验记录 |

根因不是实现，是**契约缺位**：没有人写清「启动页」和「运行期页面」是两个可以不同的表面，于是每次修 bug 都在重新定义产品。

## 决策

### 1. 启动阶段：固定品牌黑，取 logo 底色

- 启动背景固定 `#05070A`（品牌 logo 自带底色），`values/colors.xml` 与 `values-night/colors.xml` **同值**。
- 不随系统深浅、不随 App 内偏好变化。系统启动屏与 `android:windowBackground` 必须同色，交接处零色差。
- 理由：logo 是白卡车 + 黑底，浅底会把白色图形吃掉；黑底启动是品牌资产的一部分，不是"深色模式"。

### 2. 运行期：页面外观可切换

- App 内允许 浅色 / 深色 / 跟随系统，默认跟随系统。
- 启动页的黑**不外溢**到运行期：进入首页后，外观由用户偏好决定。
- 状态栏 / 系统栏跟随**页面**主题，不跟启动屏。

### 3. PR #193 的处置

- **不采纳**「固定深色主题 / 取消外观切换」的部分——与第 2 条冲突。
- 登录页品牌 Logo 与 `css/login-startup.css` 若确为改进，**另开小 PR** 单独评审，前置条件：rebase 到最新 main、`npm run assets:refresh`、`npm run csp:hashes`，并保证只用 `--zp-*` 令牌、无硬编码色。
- 该 PR 上的完整复验记录保留，作为"为什么不能整包合并"的证据。

## 可校验点（供守卫与评审对照）

| # | 断言 | 位置 |
|---|---|---|
| 1 | `values.splashBackground` == `values-night.splashBackground` == `#05070A` | 两个 `colors.xml` |
| 2 | 启动主题与常规主题的 `android:windowBackground` 均为 `@color/splashBackground` | `values/styles.xml` |
| 3 | 页面浅色底仍为 `#F6F7F9`，且深色可切换 | `css/ui-base.css` / `ui-theme.css` / `js/ui/appearance.js` |
| 4 | 启动屏退出由 `webReady` 握手决定，不由窗口首帧决定 | `MainActivity.installLaunchScreen()` |

## 后果

- **黑 → 浅的过渡是有意设计**，不再作为"闪变"缺陷处理；判断标准改为「启动屏是否保持到首帧、中间是否有空窗」。
- 任何"把启动页改成浅色/跟随系统"的提案，必须先推翻本 ADR，而不是在实现层顺手改。
- 外观切换的三个入口（系统、App 内、启动页）从此有唯一解释，PR 评审可直接引用本文。

## 未决

- 启动屏兜底超时当前为 15 秒（代码），注释仍写 6 秒；本轮只修注释，**数值待弱网冷启动实测后另定**（见体检报告 D2）。
- `webReady` 首帧标记目前是实例字段，注释却写"刻意 static"；是否改为进程级标记，待真机确认 Activity 重建路径后另定。
