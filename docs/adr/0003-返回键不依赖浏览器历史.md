# ADR 0003：返回键不依赖浏览器历史

- 状态：已采纳（2026-10-30，v1.0.19）
- 影响面：Android 壳（`MainActivity`）、`js/ui/back.js` 的退出与补压路径、管理员菜单
- 相关：`AGENTS.md` 第 8 节第 8、11 条；ADR 0002

## 背景

v1.0.18 把返回收口到「单根模型」：业务区任何页面返回 → `/home`，首页两次返回退桌面。
为了让「首页两次返回」成立，`back.js` 会在工作区根压一条占位历史，并在 Android 壳里用
`webView.goBack()` 触发 `popstate` 让 Web 控制器接管。

录屏修复（PR #53）进一步把占位限制到「只在工作区根压」，子页面不再压——否则
`location.replace` 替换的是占位而不是页面本身，旧页面记录永久残留，返回会退回内页。

这个修正是对的，但暴露了一个结构性错配：

> **`webView.goBack()` 只认「上一页文档」，不认识「当前页还开着的弹层」。**

子页面没有占位，`goBack()` 就会把整个文档换成 `/home`——运单核对页上的确认框、
历史页的筛选浮层、账户页的帮助层，连同里面未处理的输入一起被丢掉。用户看到的是
「按返回直接回首页」，而不是「先关弹窗」。

历史栈层面还有第二处错配：顶部返回按钮与原生返回键并不消费历史，但 `zpBackButton()`
在「关掉一层 UI」（`handled`）后无条件 `zpPushGuard()`。这条记录在离开本页时不会被
`replace` 替换（`replace` 只替换当前项），于是变成一个指向内页的孤儿——连按返回时
又会退回已经离开的页面，正是用户最初反馈的现象。

## 决策

1. **原生返回键一律交 `window.zpSystemBack()`，不走 `webView.goBack()`。**
   `MainActivity.handleOnBackPressed` 先探测 `window.zpSystemBack` 是否存在，存在则调用；
   JS 未就绪（首帧、脚本报错）才退回 `canGoBack()/goBack()/finish()` 兜底。
2. **退出走原生 `ZhipeiNative.exitApp()`。** `zpDoExit()` 检测到壳就立即调用 `finish()`；
   只有浏览器/PWA 环境才用 `history.back()` 越过首条记录。
3. **补压只在「下面还压着弹层」时发生**：`if(zpTopHook())zpPushGuard()`。
   层关光了就不再补，避免堆出孤儿记录。
4. **弹层/菜单不得自压历史。** 管理员菜单原有的 `history.pushState({zpMenu:1})` 删除，
   层级改由 `zpRegisterBackHook`（rank 20）表达。
5. **站内导航禁用 `location.assign()`**（与 `location.href=` 同级禁令），统一 `location.replace`。

## 理由

**1. 把「返回」的语义从平台手里收回来。**
浏览器的「返回」语义是「上一页文档」，而产品要的是「上一层界面」——弹层、抽屉、页面、
桌面，四层在同一份文档里。只有 Web 控制器知道这四层，所以决策权必须完整地给 Web，
壳只做转交。这同时让顶部按钮、物理键、手势返回三者天然一致。

**2. 不写历史就没有孤儿。**
单根模型下历史栈唯一需要的那条记录是「工作区根占位」，它服务于「两次返回退桌面」。
弹层关闭、模块切换都是文档内的层级变化，不该产生历史记录。去掉它们之后，
栈里只剩「当前页 + 根占位」，返回方向恒为「往桌面走」。

**3. 退出用 `finish()` 比 `back()` 可靠。**
WebView 里的 `history.back()` 最多退回上一页，退不到桌面；`window.close()` 对
「主页启动的顶层上下文」是空操作。`ZhipeiNative.exitApp()` 是唯一确定能结束 Activity 的出口。

## 代价

- **浏览器（含 Edge / 手机浏览器直接访问）里，返回键仍是平台行为。** 网页无法拦截浏览器的
  后退，子页面弹层会被跳过。这是平台边界，不做历史占位去凑（那样会重新引入孤儿记录，
  且用户会遇到「返回要多按一次」）。App 内不存在这个问题。
- 子页面弹层改用「关闭按钮 / 遮罩 / ESC」关闭。这三种入口本来就存在。
- 改壳必须发新 APK：`v1.0.19` 起生效，v1.0.18 及更早的壳仍走 `goBack()`。

## 约束（防回潮）

- `tests/nav-back-channel.test.mjs`（Web 仓）：
  - `MainActivity` 里 `goBack()` 必须出现在 `(window.zpSystemBack?1:0)` 之后；
  - `zpDoExit` 里 `exitApp()` 必须在 `history.back()` 之前；
  - `zpBackButton` 行为求值：还有下一层才补压（1 次），最后一层不补压（0 次）；
  - 全仓 `js/`、`pages/` 无 `location.assign(`、无 `history.pushState({zpMenu`。
- `scripts/check-back-channel.mjs`（客户端仓）：同样的原生侧断言，进 CI。
- 若未来要恢复「浏览器后退也关弹层」，必须先推翻本 ADR，并给出「弹层占位如何被消费」
  的完整方案（打开压、任何路径关闭都消费），不能只在打开处 `pushState`。
