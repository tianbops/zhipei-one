# 智配One · 全局 Android App 返回机制 v2

版本：2026-10-04
状态：已实现（代码基线）
适用：司机业务端 + 管理员端（PWA / Android WebView）

## 1. 最高原则

**返回的目标是「上一级业务上下文」，不是固定首页，也不是 `history.back()`。**

| 原则 | 说明 |
| --- | --- |
| 来源驱动 | 返回目标由 URL 的 `from=` 明确携带，禁止猜测来源 |
| 按钮等价于系统返回 | 顶部返回箭头与 Android 物理返回 / 侧滑手势走同一套代码 `zpHandleBack()` |
| 先关 UI，再退页面 | 有弹层时返回只关弹层，绝不直接离开页面 |
| 工作区隔离 | 管理员端是独立 App 工作区，永不串到业务端；反之亦然 |
| 根页防误退 | 工作区根页（首页 / 管理员面板）两次返回才退出应用 |

## 2. 统一导航模型

```
from    : 从哪里来（决定返回目标，唯一依据）
page    : 当前页面
context : 上下文（如 date= 历史日期、source= 入口类型）
id      : 业务对象 id（如 waybillId，跨页往返必须保留）
```

## 3. 中央控制器（js/ui-unified.js 底部）

| API | 作用 |
| --- | --- |
| `window.zpResolveBack(fallback)` | 按 `from=` 解析返回目标，含跨区防火墙与死循环兜底 |
| `window.zpHandleBack()` | 统一返回入口。返回 `handled` / `exit-armed` / `exit` / `leave` |
| `zpDoExit()` | 真正退出应用（置跨区标记 → `history.back()` 越界 → standalone `window.close()`）。顶部按钮与物理键共用 |
| `zpBackButton()` | 顶部返回按钮专用出口，**必须消费返回值**：`handled`→补占位、`exit`→`zpDoExit()`、`leave`→不做任何历史动作 |
| `window.zpRegisterBackHook({rank,probe,dirty,close})` | 注册一层可返回 UI（自动按 rank 排序） |
| `window.zpDirtyProbes` | 页面级「未保存修改」探测（无弹层的编辑态） |
| `window.zpGoBack(fallback)` | 直接按来源跳转（业务跳转场景） |

### 3.1 层级 ladder（rank 小者优先）

| rank | 内容 | 典型例子 |
| --- | --- | --- |
| 5 | 通用确认框 `.zp-confirm` | 放弃修改、退出登录 |
| 10 | Dialog / Bottom Sheet | 日历选择器、删除确认、上传面板、导入面板、表单弹窗 |
| 20 | Drawer / 下拉菜单 | 首页菜单、数据中心菜单、系统设置抽屉 |
| 30 | 未保存编辑态 | 表单已填写、`#confirmDialog` 已选未提交 |
| 40 | 左滑展开行 | 历史记录行、管理员列表行 |
| 50 | 页面导航 | 离开当前页，按 `from=` 回上一级 |
| 60 | 工作区根 | 两次返回才退出应用 |

> 返回值语义（改动过，务必按此实现）：`zpHandleBack` 在工作区根第二次返回时返回 **`exit`**
> （不再是 `leave`）。`leave` 现在**专指**「非根页面的普通返回」——此时 `location.replace`
> 已发起页面导航，调用方**不得**再置跨区退出标记或再 `history.back()`，否则一次返回会变成退两层、
> 甚至在详情页按返回时连带退出应用。

## 4. 来源 → 返回目标映射

| from | 返回目标 |
| --- | --- |
| `home` | `/home.html` |
| `today` | `/pages/today.html` |
| `history` | `/pages/history.html` |
| `data` | `/pages/data.html` |
| `account` | `/pages/account.html` |
| `route` | `/pages/route_apply.html` |
| `dispatch` | `/pages/dispatch.html`（线路页是一级页：数据资料 / 历史 / 我的 / 线路申请 四个出口返回都回到线路页） |
| `process` | `/home.html` |
| `order`（需带 `id`） | `/pages/order_detail.html?id=<原运单id>&source=process&from=process` |
| 缺省 | 回落到本工作区根 |

> 语义提醒：`from` 表示**从哪来**，不是当前模块名。
> 首页的六个出口一律写 `from=home`；写成模块名（如 `today.html?from=today`）会解析成返回自己而死循环。

### 4.1 常驻底部导航的来源

底部四项是**平级一级导航**，不构成历史层级。因此注入导航的链接一律写 `from=home`：
无论从哪个二级页切过去，返回都回到首页，不带来路上下文（与「从上一级业务上下文返回」区分开）。

### 4.2 路径碎片归一化 `zpNormFrom()`

历史链接与旧缓存页里存在 `from=pages%2Fdispatch` 这类「路径碎片」写法。解析前统一归一化
（去前导 `/`、去 `.html`、剥 `pages/` 前缀）再查表；未收录的来源一律回落到本区根。

### 4.3 失效上下文 `zpMarkStale()`

删除类操作（如删完当天最后一张运单）之后，按来源回跳会落到已删除的对象上——详情页变成
「运单读取失败」空态、历史页落在已删日期。此时调用 `window.zpMarkStale()` 置一次性标记，
`zpResolveBack` 直接短路回本区根，并顺带把当前历史项里的失效 `id`/`date` 摘掉。
只删其中一张、仍有剩余时不要置标记。

## 5. 跨区防火墙

管理员端是**独立 App 工作区**：四个面板（用户/线路/审核/邀请码）是平级一级页，不构成历史层级。

- 管理员端解析出的任何目标（含 fallback）若不是 `/admin.html`，一律作废回落到管理面板
- 业务端永不解析到 `/admin.html`
- 兜底：解析结果等于当前页 → 回落到本区根，杜绝死循环

### 5.1 板块隔离门禁（业务页拒绝管理员会话）

管理员端与司机端是**两个独立板块**，页面之间不留通道。除了返回目标的防火墙，业务页本身还有一道入口门禁：

- 登录页 / 管理端把本会话角色写入 `sessionStorage.zpRole`（`admin` / `user`）
- **业务区页面**加载时执行 `zpZoneGuard()`：
  1. 若 `zpExitAdmin` 置位（正在执行退出流程）→ **放行并继续后退**，绝不能弹回管理端，否则「两次返回退出」永远退不掉
  2. 否则若 `zpRole === "admin"` → 立刻 `location.replace("/admin")`，业务界面一帧都不露出
- `pageshow` 且 `persisted`（bfcache 恢复）时**再过一次门禁**：系统返回完全可能把用户带回到一个缓存的业务页，而 bfcache 恢复不会重跑页面脚本
- 退出登录一律先回登录页，**登录页进入即清空 `zpRole`**，因此换账号登录司机后不会被误判
- 管理端确认非管理员时写 `zpRole="user"` 再送 `/home`，杜绝两端互相踢皮球

> 反向通道：业务端不存在任何指向 `/admin` 的链接；业务账号访问管理端由 `admin.html` 直接送回 `/home`。

## 6. 明确禁止

- ❌ `document.referrer` 推断来源
- ❌ `history.length` 判断是否可返回
- ❌ 任意 `history.back()`（除 `admin.html` 收抽屉时自触发且已被中央控制器抑制）
- ❌ 多个 `popstate` 监听器（全站只允许 `ui-unified.js` 一个）
- ❌ 跨工作区返回

## 9. 已修复缺陷：管理员端返回穿越到业务端

**现象**：管理员在系统返回确定「再按一次退出应用」后停顿几秒，再按一次返回，页面直接落到司机业务首页 `/home.html`。

**根因**（两条叠加）：

1. **guard 占位被吃掉后没有补回来。** 页面靠一条 `pushState` 占位历史项把「系统返回」变成 `popstate` 事件。
   第一次按下会消耗掉它；若随后的 2 秒确认窗口正常过期，旧代码只把 `zpExitArmed` 复位，
   **页面从此赤裸地停在 history 栈顶**——下一次返回浏览器就直接滑出本页，落到历史里的上一个文档。
   真人操作几乎必然停顿，所以这个缝隙很容易被踩到。
2. **登录页在回退时仍按角色自动直达。** `index.html` 的 `/api/me` 自动跳转没有区分「冷启动」和
   「用户退回来的」，管理员被送到司机首页（或反向穿越）。

**修复**（三层）：

| 层 | 位置 | 做法 |
| --- | --- | --- |
| 1 | `js/ui-unified.js` | 新增 `zpPushGuard()`，`handled` 分支与「确认窗口过期」分支都补回占位；引入 `zpGuardDepth`，确认离开时 `history.go(-depth)` 一次性跨过所有占位 |
| 2 | `js/ui-unified.js` | PWA 独立模式下确认离开时先尝试 `window.close()` 真正收起 App，300ms 未果再回退到 `history.go(-depth)` |
| 3 | `index.html` | `performance.getEntriesByType("navigation")[0].type === "back_forward"` 时不做角色直达，停在登录页由用户决定 |

**验证**：`tests/e2e-admin-back-leak.cjs` 构造「管理员页背后就是司机首页」的真实历史栈并 `history.back()`，
修复前产物为 `/home.html`（与线上现象一致），修复后稳定停在 `/admin.html`。

## 10. 已修复缺陷：standalone（桌面图标启动的 PWA）管理员端「两次返回退出」失效

**现象**：浏览器里登录进管理员页、系统返回正常；但从**桌面图标启动的 PWA（独立模式）**登录进管理员页后
系统左滑返回，会落到司机业务首页 `/home.html`，而不是「再按一次退出 → 退回手机桌面」。

**根因**：安卓独立 PWA 下 `window.close()` 对「主页启动的顶层上下文」是**空操作**，唯一可靠的退出方式是让浏览器
越过「首条历史记录」去关掉 PWA。旧实现离开时只 `history.go(-占位深度)`，在管理员页背后没有业务页时只会停在管理端、
背后有业务页（多因 PWA 标签历史被恢复，背后残留司机首页）时则落到 `/home.html`。

**修复**：

| 层 | 位置 | 做法 |
| --- | --- | --- |
| 1 | `js/ui-unified.js` | `zpHandleBack` 工作区根：第一次返回只提示「再按一次退出」并**停留**（不再补占位）；窗口过期仅复位 `zpExitArmed`，不补占位 |
| 2 | `js/ui-unified.js` | 确认离开时 `history.back()` 一步越过首条记录，由系统退回手机桌面；独立模式再尝试 `window.close()`（失败则由上一步兜底） |
| 3 | `js/ui-unified.js` | 跨区退出标记 `zpExitAdmin`：管理员确认离开时置位；业务端页（全新加载或 bfcache 恢复触发 popstate）消费标记并继续后退，直到真正退出 PWA，**绝不停在司机首页**；登录/管理端页清掉残留标记，避免重开误退 |

**关键约束（Web 平台限制）**：

- Chrome 把 `history.go(-history.length)`（越过首条记录）**钳制为空操作**，所以离开只能靠「当前已在首条记录上再 `back()` 一步」实现——这正是第 2 层不补占位的动机。
- 全新启动的 PWA（start_url → index → `location.replace` 到 admin）历史里**没有**业务页背后，两次返回即退出（headless 验证为「退出/blank」）。
- 若 PWA 标签历史被恢复、背后残留司机首页：管理员两次返回会先退到首页、再退一步真正退出，不会停在首页。
headless 测试环境无法模拟「关闭标签页/退出 PWA」，故「历史背后有首页」的退出无法由自动化断言（`tests/e2e-admin-back-leak.cjs` 仅能确认标记被消费、无残留、不卡死）。

**验证脚本**：`tests/e2e-admin-back-leak.cjs`（场景 A/B/B2/C 均正确退出）、`/tmp/navtest/verify-admin-home-leak.cjs`（跨区标记消费）。

## 11. 管理员端「完全独立工作区」（window.open 独立窗口）——已回滚，仅存档

> ⚠ **状态说明（2026-10-09）**：本节方案已在提交 `981746bb` 中**回滚**——`window.open` 在安卓
> 会被当成系统弹窗，首次左滑先关弹窗再回首页，体感更差。现行实现仍是 §9/§10 的
> 「跨区防火墙 + `zpExitAdmin` 标记 + 越过首条记录退出」，本节仅作历史存档，不要照此实现。

**背景**：§9、§10 的跨区防火墙/标记方案能让"管理员两次返回"尽量不落到司机首页，但本质是**同一浏览上下文内**的补丁——
只要历史栈里还压着业务页（典型路径：司机端 `home.html` → 点「账号设置」`pages/account.html`（push）
→ 退出登录 `location.replace("/")`（只换当前项，home 仍在栈底）→ 登录为管理员 `location.replace("/admin.html")`），
管理员页底下就压着 `home.html`，任何时序缝隙（尤其"看完提示隔几秒再按"）都可能把系统返回滑到司机首页。用户明确要求"**完全把管理员设置页独立出来**"。

**方案**：登录/切换为管理员时，**以 `window.open` 打开一个独立窗口**（仅独立 PWA `display-mode: standalone` 下启用，浏览器沿用原 `replace`）。
独立窗口拥有**独立的历史栈**，其栈里只有 `[admin.html]`，系统返回只在管理员历史内生效，**结构上不可能穿越到司机首页**；
数据仍同源共享（cookie / localStorage / 接口），即"独立工作区、数据相连"。

| 层 | 位置 | 做法 |
| --- | --- | --- |
| 1 | `js/login.js` / `index.html` | 独立 PWA 下，管理员角色命中时 `window.open("/admin.html?v=…","_blank")` 打开独立窗口并 `return`；被弹窗拦截（极少数无手势场景）时退回 `location.replace`（由下方跨区防火墙兜底） |
| 2 | `js/ui-unified.js` | `zpInstallBack` 进入即判定 `zpAdminNonRoot = (管理员端 && history.length>1)`；同窗口进入且非根时置 `zpExitAdmin` 标记，保证任何一次离开都能越过业务端首页、退回桌面而非停在司机首页 |
| 3 | `js/ui-unified.js` | 窗口过期（`zpExitTimer`）仅当 `zpAdminNonRoot` 时才补占位——独立窗口（根）不补，保证停顿后下一次返回能越过首条记录由系统退回桌面；同窗口非根补占位，保证停顿后再按重新武装而非滑到司机首页 |

**为什么这套能彻底解决"线路管理/线路审核/邀请码左滑返回到用户首页"**：那三个页面都是 `admin.html` 内的面板（同文档），
独立窗口的历史栈只有 `[admin.html]`，底下没有任何业务页，系统返回无论按几次都只在管理员历史里打转 / 退回桌面，物理上无法到达 `/home.html`。

**验证脚本**：

- `tests/e2e-admin-standalone-isolation.cjs`：模拟 `display-mode: standalone`，以管理员登录，确认 `window.open` 打开**独立 admin 窗口**，
  从该窗口返回停在 `/admin.html` 并提示「再按一次返回退出应用」，**绝无业务端可穿越**（headless 下独立窗口历史会多一条 `about:blank` 初始条目，属测试环境假象）。
- `tests/e2e-admin-back-leak.cjs` + `/tmp/navtest/verify-admin-home-leak.cjs`：同窗口非根兜底场景，构造"管理员页背后就是司机首页"，
  **停顿 3 秒后第二次返回仍停在 `/admin.html`**（不再落到 `/home.html`），标记 `zpExitAdmin=1` 就绪可越界。
