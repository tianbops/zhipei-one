# 智配One · 全局 Android App 返回机制 v2

版本：2026-10-04
状态：已实现（代码基线）
适用：司机业务端 + 管理员端（PWA / Android WebView）

## 1. 最高原则

**返回的目标是「上一级业务上下文」，不是固定首页，也不是 `history.back()`。**

| 原则 | 说明 |
| --- | --- |
| 来源驱动 | 返回目标由 URL 的 `from=` 明确携带，禁止猜测来源 |
| 按钮等价于系统返回 | 顶部返回箭头与 Android 物理返回 / 侧滑手势走同一套代码 `zpHandleBack()` |
| 先关 UI，再退页面 | 有弹层时返回只关弹层，绝不直接离开页面 |
| 工作区隔离 | 管理员端是独立 App 工作区，永不串到业务端；反之亦然 |
| 根页防误退 | 工作区根页（首页 / 管理员面板）两次返回才退出应用 |

## 2. 统一导航模型

```
from    : 从哪里来（决定返回目标，唯一依据）
page    : 当前页面
context : 上下文（如 date= 历史日期、source= 入口类型）
id      : 业务对象 id（如 waybillId，跨页往返必须保留）
```

## 3. 中央控制器（js/ui-unified.js 底部）

| API | 作用 |
| --- | --- |
| `window.zpResolveBack(fallback)` | 按 `from=` 解析返回目标，含跨区防火墙与死循环兜底 |
| `window.zpHandleBack()` | 统一返回入口。返回 `handled` / `exit-armed` / `leave` |
| `window.zpRegisterBackHook({rank,probe,dirty,close})` | 注册一层可返回 UI（自动按 rank 排序） |
| `window.zpDirtyProbes` | 页面级「未保存修改」探测（无弹层的编辑态） |
| `window.zpGoBack(fallback)` | 直接按来源跳转（业务跳转场景） |

### 3.1 层级 ladder（rank 小者优先）

| rank | 内容 | 典型例子 |
| --- | --- | --- |
| 5 | 通用确认框 `.zp-confirm` | 放弃修改、退出登录 |
| 10 | Dialog / Bottom Sheet | 日历选择器、删除确认、上传面板、导入面板、表单弹窗 |
| 20 | Drawer / 下拉菜单 | 首页菜单、数据中心菜单、系统设置抽屉 |
| 30 | 未保存编辑态 | 表单已填写、`#confirmDialog` 已选未提交 |
| 40 | 左滑展开行 | 历史记录行、管理员列表行 |
| 50 | 页面导航 | 离开当前页，按 `from=` 回上一级 |
| 60 | 工作区根 | 两次返回才退出应用 |

## 4. 来源 → 返回目标映射

| from | 返回目标 |
| --- | --- |
| `home` | `/home.html` |
| `today` | `/pages/today.html` |
| `history` | `/pages/history.html` |
| `data` | `/pages/data.html` |
| `account` | `/pages/account.html` |
| `route` | `/pages/route_apply.html` |
| `process` | `/home.html` |
| `order`（需带 `id`） | `/pages/order_detail.html?id=<原运单id>&source=process&from=process` |
| 缺省 | 回落到本工作区根 |

> 语义提醒：`from` 表示**从哪来**，不是当前模块名。
> 首页的六个出口一律写 `from=home`；写成模块名（如 `today.html?from=today`）会解析成返回自己而死循环。

## 5. 跨区防火墙

管理员端是**独立 App 工作区**：四个面板（用户/线路/审核/邀请码）是平级一级页，不构成历史层级。

- 管理员端解析出的任何目标（含 fallback）若不是 `/admin.html`，一律作废回落到管理面板
- 业务端永不解析到 `/admin.html`
- 兜底：解析结果等于当前页 → 回落到本区根，杜绝死循环

## 6. 明确禁止

- ❌ `document.referrer` 推断来源
- ❌ `history.length` 判断是否可返回
- ❌ 任意 `history.back()`（除 `admin.html` 收抽屉时自触发且已被中央控制器抑制）
- ❌ 多个 `popstate` 监听器（全站只允许 `ui-unified.js` 一个）
- ❌ 跨工作区返回

### 7.1 真机回归清单（自动化无法替代，需人工过一遍）

| # | 场景 | 期望 |
| --- | --- | --- |
| 1 | 首页侧滑返回一次 | 提示「再按一次返回退出应用」，不退出 |
| 2 | 首页 2 秒内再侧滑 | 退出 PWA |
| 3 | 首页上传面板打开时返回 | 关面板 / 处理中则提示且绝不退出 |
| 4 | 运单详情 → 数据资料 → 返回 | 回到**原来那张**运单详情（不是首页） |
| 5 | 历史 → 某日 → 返回 | 回到历史列表 |
| 6 | 今日运单 → 详情 → 返回 | 回到今日运单 |
| 7 | 识别/规划完成 → 详情 → 返回 | 回首页（保持既有规则） |
| 8 | 数据中心打开导入面板输入后返回 | 弹「放弃修改？」，取消→留在面板，放弃→关面板 |
| 9 | 数据中心改了门店未提交，直接返回 | 弹「放弃修改？」后再决定 |
| 10 | 顶部返回箭头 vs 系统返回（每条 4~8） | 行为完全一致 |
| 11 | 管理员：打开表单输入后返回 | 先弹放弃确认，绝不跳业务端 |
| 12 | 管理员：打开系统设置抽屉返回 | 收抽屉，不退出 |
| 13 | 管理员：面板根两连返回 | 第二次才退出 |
| 14 | 任何页面返回 | 不出现「点一次退两层」或「死循环回自己」 |

## 8. 版本与缓存

- Service Worker `VERSION = zp-pwa-3`：`cacheKeyOf` 只看 pathname（不带 `?v=`），改 JS 必须 bump，否则新旧脚本混用
- 每次修改 `js/*.js` 后执行 `python3 tools/stamp_assets.py` 刷新 `?v=` 戳
