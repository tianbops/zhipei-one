# 智配One 全新重建计划

版本：2026-09-26

## 重建原则
1. 删除旧业务实现，不在旧代码上继续打补丁。
2. 保留过去已经验证的业务规则、故障根因和测试经验。
3. Redis 测试业务数据清空后重新建立。
4. 单一业务链：OCR → Extract → Match → Plan → Save。
5. 客户端不复制业务规则，统一调用服务端。
6. 管理员与配送业务彻底隔离。
7. boundRouteId 与 dispatchRoute 永远分离。
8. 路线是独立系统实体；每条线路最多一名司机和一名配送员。
9. 待定/新增门店确认后才允许写入基准库和学习数据。
10. 每个核心阶段都必须通过真实运单回归后才能进入下一阶段。

## 重建阶段
- Phase 1：干净代码基线、认证、统一 API、基础数据模型
- Phase 2：线路与权限
- Phase 3：OCR 与提取
- Phase 4：匹配、待定、新增、去重
- Phase 5：规划与保存
- Phase 6：今日线路、历史、学习闭环
- Phase 7：Web UI、管理端、小程序接口
- Phase 8：真实运单全链路回归
